# ESP32-S3 × WiFi CSI 家庭人体感知系统 — 项目实施方案

> **目标**：家庭室内 **1–2 人**的**活动识别 + 呼吸监测**，非接触、无摄像头、无穿戴
> **架构决策**（已确认）：现场无上位机 → 呼吸/存在检测跑在 ESP32-S3 端上，活动识别模型跑在远程服务器；自建轻量后端（非 Home Assistant）；硬件尚未采购
> **依据**：论文结论与开源项目调研见 `E:\ObsidianVault\tech\raw\papers_wifi-csi\README.md`（15 篇论文知识库 + 工程路线图，本方案引用其结论，标注〔论文〕/〔开源〕来源）

## 1. 项目概述

### 1.1 目标与验收指标

| 功能 | 指标 | 验收标准 | 依据 |
|------|------|----------|------|
| 呼吸监测（单人静止） | 呼吸率误差 | 30s 窗（可调至 60s），MAE ≤ 2 bpm，±2 bpm 命中率 ≥ 90% | Serene 真实家庭中位 1.19 bpm〔论文 B1〕 |
| 体动门控 | 有效性判断 | 走动/翻身期间正确挂起 ≥ 90%，误挂起 ≤ 10% | Vital-Radio 准静态窗口〔论文 B4〕 |
| 存在检测 | 无人/有人 | 准确率 ≥ 95%（同房间 LOS） | esp-csi 官方例程已实现〔开源〕 |
| 活动识别（单人，监测区内） | 4 类：无人/静止/走动/跌倒 | 总体准确率 ≥ 85%，**跌倒召回 ≥ 90%**（限监测区内脚本化跌倒，宁误报不漏报） | Yousefi 跌倒 94% 为 Intel 5300 @1kHz 实验室条件，本项目条件更弱，故限定范围〔论文 A2〕 |
| 人数粗判（双人） | 0/1/2 人 | 0/1 人 ≥ 95%；2 人 ≥ 80%（**探索性目标**，M4 验证后定标） | Wi-Vi 2 人 85%（USRP+MIMO 强硬件条件）〔论文 B5〕 |
| 双人呼吸 | 主用户误差 | ≤ 3 bpm（次用户可降级） | TensorBeat 2–3 人 93% <0.5 bpm〔论文 B3〕 |
| 端到端延迟 | 呼吸结果更新 ≤ 10s；活动**状态变更检出** 3–5s（2s 窗/0.5s 步进） | — | 窗长与延迟物理上限一致（见 §7） |

> 指标锚定原则：验收线不高于所引证据在其硬件条件下的实测值；证据条件强于本项目的（如 Wi-Vi、Yousefi），验收线须回调或限定适用范围。

### 1.2 非目标（明确不做）

- **医疗级监测**：Serene 结论——性能可比脉冲雷达但不足以医疗级，产品口径定位"日常趋势"。
- **身份识别**：Avola 已证明 ESP32 可行（99.82%），留作二期可选。
- **穿墙远距/多房间**：本期限同房间 LOS ≤ 5m；多房间靠多套设备覆盖。
- **监测区外的跌倒承诺**：家庭跌倒高发区（卫生间、走廊）不在床/沙发 LOS 监测区内，本方案只承诺监测区内跌倒检测，全区覆盖需增设设备（二期）。
- **3 人以上**：综述共识多用户并发 ≤ 3 人且精度骤降，本项目锚定 1–2 人。

### 1.3 关键硬件事实（影响所有设计，已经独立评审核实）

- **ESP32-S3 仅支持 2.4GHz**（802.11 b/g/n，官方规格支持 40MHz 带宽）。WiMANS 的"5GHz 优于 2.4GHz"结论**不适用**；对策：选干净信道，HT40 仅作调优选项（视路由器能力，见 §4）。
- **子载波数**：
  - **HT20（默认）**：学术主流口径 **52 个有效子载波**（Wi-ESP 论文、Avola、esp-csi 工具链解析）；CSI-Bench 报"ESP32-S3 在 20MHz 下 64 个 CSI 值"——**52 与 64 的口径差异（原始缓冲含无效/填充值）必须在 M0 实测确认解析规则**（esp-csi 已知 issue #45/#137：CSI 缓冲前若干字节无效）。
  - **HT40（调优选项）**：实际输出 **128 个复数值**（802.11n 规范有效子载波约 114），非 64。
- **CSI 采样 100Hz**：esp-csi 官方 `csi_send` 例程默认值即 100 包/s；Avola、CrossFi（S3）均按 100Hz 实测〔已核实〕。
- 单天线无天线间相位差 → **以幅度为主**（CSI-Bench 的"仅幅度"策略已被验证足以支撑呼吸任务）。

## 2. 总体架构

```
┌─────────────── 家庭现场（无上位机）───────────────┐      ┌──── 远程服务器（VPS）────┐
│                                                    │      │                          │
│  [TX 板 ESP32-S3]          [RX 板 ESP32-S3]        │      │  Mosquitto (MQTT/TLS)   │
│  周期发包(ESP-NOW)     →   CSI 提取 (100Hz)        │      │       ↓                  │
│  固定信道，仅供电          ↓                       │ WiFi │  ┌────────────────┐     │
│                           端上算法（C, ESP-DSP）：  │ 经由  │  │ FastAPI 服务   │     │
│                           ① 预处理+体动门控        │ 家用  │  │ · CSI/特征入库  │     │
│                           ② 呼吸率估计             │ 路由  │  │ · 活动模型推理  │     │
│                           ③ 存在/人数粗判          │ 仅出站│  │ · 少样本适配    │     │
│                           ↓                       │ 连接  │  └────────────────┘     │
│                      MQTT/TLS 发布(结果+特征) ───────────→  SQLite + Grafana        │
│                      断网时本地自治+缓存            │      │  (反代后, 带鉴权)        │
└────────────────────────────────────────────────────┘      └──────────────────────────┘
```

**职责划分原则**：断网时必须仍可用的功能（呼吸、存在）在端上；需要模型迭代的功能（活动分类）在服务器——换模型不重刷固件。

**上行数据策略**（带宽估算，避免设计失误）：

| 数据 | 速率 | 体积/天 | 用途 |
|------|------|---------|------|
| 呼吸结果 + 有效位 | 每 10s 一条 JSON | < 1 MB | 常态 |
| 活动特征段（降采样 CSI，10Hz × 52 × int8） | 流式 | ≈ 45 MB | 常态（服务器推理） |
| 原始 CSI（100Hz 全量） | — | ≈ 1.8 GB/天（float32） | **仅调试模式**（串口本地落盘，不上传） |

## 3. 技术选型

| 层 | 选型 | 理由 |
|----|------|------|
| 固件框架 | **ESP-IDF 5.x（C）**，官方推荐 v5.0+ | CSI API 原生（`esp_wifi_set_csi_rx_cb`）；esp-csi / esp32-csi-tool 均基于 IDF |
| 采集固件骨架 | **espressif/esp-csi**（`examples/esp-radar/console_test` + `csi_send`）〔开源 ⭐1.6k〕 | 官方维护、双板 ESP-NOW 收发例程齐全、自带标定与可视化脚本；数据格式参考 ESP32-CSI-Tool 的 CSV 惯例 |
| 端上算法库 | **ESP-DSP**（乐鑫官方） | FFT/IIR(biquad)/矩阵运算现成；**Hampel 与滑窗统计需手写**（量小，可承受） |
| 上行协议 | **MQTT over TLS(8883)**，每设备独立凭据 | 轻量、断线重连、QoS；呼吸属健康敏感数据，必须加密（见 §9） |
| 后端 | **Python FastAPI + SQLite** | 轻量自建；数据量小起步，后期可换 TimescaleDB |
| 活动模型 | PyTorch：CNN-5 / CNN+GRU（≈0.3–2M 参数） | SenseFi 基准结论：浅层最优，深网跨域 <20%〔论文 C2〕；跨环境用 CrossFi 少样本模板〔论文 C3〕 |
| 仪表盘 | **Grafana**（读 SQLite/MQTT） | 免自绘；置于反代后加鉴权，不直接暴露公网 |
| 服务器落地 | **轻量 VPS + 域名 + Caddy 反代统一 TLS** | 家用宽带无公网 IP，设备仅出站连接；成本 ≈ ¥50–100/月（2C2G VPS + 域名） |
| 标注工具 | 事件表（CSV：起止时间+类别）+ 瀑布图对照 | 参照 ESP32-CSI-Tool 手机标注思路，简化为表格 |

| 外壳 | 2（可选） | 3D 打印或现成塑料盒，天线外露 | — |

**部署形态与约束**：

- TX、RX 靠墙插座供电，间距 3–5m，监测区（床/沙发）在 LOS 路径上；RX 板以 STA 连家用路由器负责上行，**TX 的 ESP-NOW 信道必须与路由器信道一致 → 路由器固定信道**。
- **带宽一致性**：STA 带宽跟随 AP；2.4GHz 多数家用路由默认甚至强制 20MHz（拥挤时自动回退），且 ESP-NOW HT40 需与 AP secondary channel 方向（ABOVE/BELOW）一致。**默认 HT20，HT40 仅在路由器支持且实测增益明确时启用**。
- **TX 板无 WiFi 上行**：固件更新走 USB 重刷；如需远程更新，二期预留 RX→TX 的 ESP-NOW 控制信道。
- 许可注意：espectre 为 GPLv3/商业双许可——**对照借鉴设计无碍，直接合入其代码需评估传染性**。

## 5. 里程碑计划

### M0 环境搭建与 CSI 跑通（第 1–2 周）
1. 下单 BOM；安装 ESP-IDF 5.x + 工具链（VSCode 插件或 CLI）。
2. clone `espressif/esp-csi`，TX 烧 `csi_send`、RX 烧 `examples/esp-radar/console_test`，串口实时看 CSI。
3. **CSI 配置定稿与口径确认**（评审 P0-1/P2-1）：确定 `lltf_en/htltf_en/stbc_htltf2_en/ltf_merge_en/manu_scale/shift` 配置组合（从 csi_recv 默认全开起步）；实测确认子载波数量与有效值解析规则（52 vs 64@20MHz 口径、缓冲前无效字节）。
4. **固件检查单**：`esp_wifi_set_ps(WIFI_PS_NONE)` 关闭 modem-sleep（否则 STA 省电模式会丢 ESP-NOW 包，官方 csi_send 源码即如此设置）。
- **验收**：连续 1h 无重启；采样率稳定 100Hz（±5%）；丢包率 ≤ 1%；子载波解析规则有书面结论；幅度随人移动可见变化。

### M1 数据工具链（第 3–4 周）
1. 自研采集固件：TX 周期发包（速率可配）+ RX CSI→环形缓冲→CSV（串口本地）与 MQTT 双输出。
2. Python 分析管线（**兼作 M2 端上算法的黄金参考实现**）：CSI 解析 → 清洗 → **瀑布图（子载波×时间幅度热图）** → 事件标注表。
3. 采集第一批数据（管线验证量级）：无人 / 静止坐 / 静止躺 / 缓慢走动 / 深呼吸刻意控制，每场景 ≥ 30min × 多时段。
- **验收**：瀑布图上能肉眼辨识呼吸周期条纹；数据集带标注入库。

### M2 呼吸监测 v1（第 5–7 周，端上，验收分两档）
- **M2a（第 5–6 周）跑通与对拍**：按 §6 管线先完成 Python 黄金实现，再移植端上 C + ESP-DSP；**对拍验收**：同一 CSV 输入，Python 与 C 输出逐窗 bpm 差 ≤ 0.2 bpm、体动判定一致率 ≥ 99%（该对拍脚本兼作后续固件回归测试）；实现 §6 校准规程。
- **M2b（第 7 周）真值达标**：真值对照（节拍器引导呼吸 / 视频胸廓起伏计数，每 session ≥ 5min）；**验收**：静止单人 MAE ≤ 2 bpm；走动期间正确挂起 ≥ 90%；断网时本地结果继续更新、恢复后补传。

### M3 活动/存在识别 v2（第 8–11 周，服务器）
1. 后端搭建：VPS + 域名 + Caddy TLS + Mosquitto(8883) + FastAPI + SQLite + Grafana 骨架（§9 安全要求同步落地）。
2. 基线先行：经典特征（滑窗方差/均值/频谱能量）+ SVM/随机森林——快速打通端到端链路。
3. 深度模型：CNN-5 或 CNN+GRU（可从 UT-HAR 公开数据预训练再自采微调〔SenseFi 代码库可直接改造〕）。
4. 与端上体动门控联动：体动期不输出活动分类或输出"体动"类。
- **前置数据门槛**（不满足则先补采集）：每类 ≥ 30min × ≥ 3 天 × ≥ 2 位置（或每类 ≥ 500 窗），跨天/跨位置样本强制入测试集。
- **验收**：单人 4 类 ≥ 85%（监测区内），跌倒召回 ≥ 90%（脚本化跌倒）；Grafana 实时曲线/状态可用；活动状态变更检出 3–5s。

### M4 双人场景与失效演练（第 12–14 周）
1. 人数粗判：空间方差/多子载波相关特征分类 0/1/2 人〔Wi-Vi 思想〕（0/1 为硬验收，2 人探索性）。
2. 双人呼吸：谱峰配对（简化 TensorBeat；完整 CP 分解在服务器离线跑，不上端）。
3. 失效模式演练：被子覆盖、朝向改变、旁人走动、NLOS——按 README §3.4 对策表逐项过，失效场景须有明确降级行为（输出"无效"而非错误值）。
- **验收**：0/1 人 ≥ 95%（2 人 ≥ 80% 探索性）；主用户呼吸 ≤ 3 bpm。

### M5 泛化适配与产品化（第 15 周起）
1. 泛化与少样本适配：换房间部署，每类 1 样本重建模板〔CrossFi 1-shot 91.72%〕；跨天/跨位置复测。
2. 产品化：OTA（仅 RX 板，esp_https_ota + 签名 + 双分区回滚）；72h 连续运行稳定性；外壳安装；仪表盘完善（呼吸趋势日报、活动时间线、房间占用）。

## 6. 端上呼吸算法规格（v1）

```
输入 CSI(100Hz, 52 子载波, 幅度)
 → ① Hampel 去野点：窗 15（=0.15s@100Hz）, β=3    〔Avola——注意：该参数为 100Hz 域，不可在降采样后沿用〕
    （顺序约束：必须先去野点、后滤波降采样——冲激型野点一旦被低通展宽即混入呼吸带，事后无法剔除）
 → ② 抗混叠低通 + 降采样 100Hz→10Hz（呼吸带宽 <0.6Hz，10Hz 足够；WiRM 用 9.9Hz 达 SOTA）
 → ③ 去 DC：滑窗均值扣除；可选一阶差分消静态多径 〔Serene〕
 → ④ 子载波聚合：
     v1.0 选呼吸频段(0.1–0.6Hz)DFT 信噪比最高的 top-K 子载波求平均 〔WiRM 思路〕
     v1.1 PCA 第一主成分（服务器离线算好 52 维权重，下发固件）    〔Serene〕
 → ⑤ 带通 0.1–0.6Hz（6–36 bpm），4 阶 Butterworth 〔Serene 10–40bpm 放宽下限覆盖睡眠/老人〕
 → ⑥ 频率估计：30s 滑窗(300点@10Hz, 补零至512) FFT
     抛物线插值峰值 + 自相关周期交叉验证      〔TensorBeat/Serene〕
 → ⑦ 体动门控（两级）：
     a) 7.5s 短窗功率 vs 校准噪声基底（见下）
     b) FFT 峰值功率 ≥ 5× 谱均值才判有效      〔Vital-Radio〕
     任一不满足 → 挂起输出，置无效标记
 → ⑧ 相干轨迹确认（2026-10-06 实装）：宽进（两法一致 & 峰值比≥2.0 & 功率非尖峰）
    → 严出（±45s 邻域候选≥5 且与邻域中位差≤0.5bpm）——呼吸窗锁定同一频率轨迹，
    走动/干扰伪窗散乱出局；实测仰卧覆盖 26%→72%、侧卧 0%→可用、走动 0% 误报
 → ⑨ 丢包降级守卫：loss>20% 挂起输出（拥塞链路重采样伪影会形成假相干轨）
 → 输出：bpm + valid + confidence(峰值显著度)，MQTT 每 10s 上报
```

**校准规程（体动门控的地基，评审 P1-6）**：

- **无人基线标定**：每次部署采集 ≥ 10min 无人 CSI，累积各子载波噪声基底；流程参考 esp-csi console_test 自带标定（delay/duration/阈值累积）。
- **重标触发条件**：挪动家具/换季/断电重启后；运行期基底漂移监控（滑动统计越限告警）。
- **阈值存储**：以"基底 + k·σ"形式存 NVS，k 可 OTA 调整。
- 校准规程完成纳入 M2a 验收。

参数集中在固件配置区，全部对应 README 论文出处，便于回归论文调参。

## 7. 服务器活动识别规格（v2）

- **输入**：流式特征段（10Hz × 52 int8 降采样 CSI，**2s 窗、0.5s 步进滑窗**）。
- **延迟口径**：状态变更检出延迟 = 窗长 + 推理 + 传输 ≈ 3–5s（§1.1 与此处一致；2s 窗下不可能 ≤2s）。
- **基线**（M3 前半）：滑窗统计特征（方差、均值漂移、频谱能量分布、子载波间相关）+ SVM。
- **主模型**（M3 后半）：CNN-5 或 CNN+GRU，输入 52×T 幅度谱；训练集 = 自采标注数据（满足 §5 M3 数据门槛）；可选 UT-HAR 预训练〔SenseFi〕。
- **类别体系**：无人 / 静止（坐躺）/ 走动 / 跌倒（+体动过渡类）；**类别收紧是精度达标的先决条件**〔WiMANS：多人 HAR 仅 60–65%〕；跌倒类仅对监测区内生效（§1.2）。
- **新环境适配**（M5）：换部署位置后每类采 1 个样本重建类模板〔CrossFi〕；进阶 TTA〔DATTA〕。
- **推理节奏**：特征段到达即推理；体动门控无效期不分类。

## 8. 数据与评估规范

- **自采数据集命名**：`场景_人员_位置_日期`；标注事件表 CSV（start,end,label）；元数据 JSON（固件版本、信道、带宽、间距、朝向）。
- **数据规模门槛**：M1 首批为管线验证量级（每场景 ≥30min）；M3 模型训练门槛见 §5（每类 ≥30min × ≥3 天 × ≥2 位置）。
- **呼吸真值**：节拍器引导呼吸（±误差已知）或视频胸廓起伏人工计数；每 session ≥ 5min。
- **跌倒采集规程**（评审 P1-4）：限监测区内；动作脚本化（前向/侧向/缓慢滑坐）；安全措施（软垫、陪护）；每方向 ≥ 20 次 × ≥ 2 人；标注精确到起止帧。
- **评估集**：每人每场景留出 20% 做测试；**跨天/跨位置样本必须出现在测试集中**（模拟 OOD〔CSI-Bench 教训：OOD 是真实杀手〕）。
- **指标**：呼吸 MAE / ±2bpm 命中率；活动混淆矩阵 + 宏 F1 + 跌倒召回；门控误报/漏报率；**端上 C vs Python 黄金实现对拍**（逐窗 diff，兼作回归测试）。

## 9. 安全与运维（评审 P1-5/P1-8）

- **传输**：MQTT over TLS(8883)；每设备独立用户名/密码（或客户端证书）；设备仅出站连接，不开放入站端口。
- **服务器**：VPS + 域名，Caddy 反代统一 TLS 终止；FastAPI/Grafana 不直接暴露公网，Grafana 启用账号鉴权；SSH 仅密钥登录。
- **OTA**：仅 RX 板；`esp_https_ota` + 镜像签名校验 + 双分区自动回滚；TX 板 USB 重刷（§4）。
- **数据**：呼吸率属健康敏感数据——SQLite 落加密盘、按保留期清理；每日快照备份出 VPS。
- **成本**：2C2G VPS + 域名 ≈ ¥50–100/月。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 2.4GHz 信道拥塞（家邻环境） | CSI 信噪比下降、丢包 | 部署期扫描选干净信道并固定路由器；HT40 视路由器支持作为调优选项；发包速率自适应 |
| 52/64 子载波口径不清 | 解析错位 → 全管线错误 | M0 实测定稿解析规则（§5 M0-3），写入固件常量与文档 |
| 跨域掉点（换房间/换人） | 活动识别 F1 可能从 88% 掉到 46–58%〔CSI-Bench OOD〕 | 少样本模板重建为标准流程（M5）；评估集必含跨天/跨位置 |
| 呼吸信号弱（距离 >5m / NLOS / 侧卧朝向） | 误差增大甚至失锁 | 部署约束写入验收（同房间 LOS）；体动门控兜底输出"无效"而非错值 |
| 上行带宽/流量 | 全量原始 CSI 1.8GB/天不可接受 | 常态只传结果+降采样特征（≈45MB/天）；原始 CSI 仅调试本地落盘 |
| 服务器不可达 | 活动识别中断 | 端上呼吸/存在自治 + 结果缓存补传；活动降级为"体动/静止"粗分类 |
| 双人信号混叠 | 双人呼吸互相污染 | 主用户优先策略；完整 CP 分解只在服务器离线提供 |
| 单天线无相位信息 | 相位类方法不可用 | 幅度为主（已验证可行）；不做需要多天线的方案（WiRM 共轭法等） |
| M2/M4 进度偏紧 | 延期 | M2 已拆两档验收（跑通对拍 → 达标）；M4 已砍掉泛化适配至 M5；再延期则 2 人指标降为探索性 |
