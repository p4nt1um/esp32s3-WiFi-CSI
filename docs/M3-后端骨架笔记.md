## 2. 本阶段踩坑

| 坑 | 解法 |
|----|------|
| **Hyper-V 保留端口段**：1883 与 8123 都在 `netsh ... excludedportrange` 内，bind 被拒 | 开发端口改 **11883**（broker）/ **18000**（API）；排查命令记录在 backend/README |
| `drop` 是 SQLite 关键字 | 列名改 `drop_cnt` |
| paho-mqtt v2 的 `rc` 是 ReasonCode 对象，`int(rc)` 抛 TypeError | 直接 `rc == 0` 比较 |
| Windows 进程退出后文件句柄异步释放 | e2e 清理改 best-effort 重试 |

## 3. 设计决策

1. **时间戳以服务器为准**（设备时钟不可信），设备端 `t` 仅作对账。
2. amp（1Hz×52 子载波）**不落库**，只刷新设备活跃状态——量级 4.5M 行/天无查询价值；呼吸结果 1 行/10s 才是持久化主体。
3. 单 SQLite 连接+锁：写入频率每设备 ~0.2 行/s，锁竞争可忽略；换 Postgres/TimescaleDB 的触发条件写入 README。
4. 仪表盘先用自绘 canvas（零外部依赖），Grafana 仍是 VPS 部署时的正式选项。
