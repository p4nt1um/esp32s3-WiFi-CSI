# 上板笔记（2026-10-05）——双板联调全记录

> COM12=RX 板（CH343 串口桥），COM13=TX 板（S3 原生 USB-Serial/JTAG 口）。**最终状态：自研双板固件 CSI 全链路跑通**，60s 无人基线已采集并过管线。

## 1. 关键结论（覆盖 M0 遗留问题）

| 问题 | 实测答案 |
|------|----------|
| **子载波口径（M0-3 定稿）** | **HT20 → len=128 → 64 个复数值**（CSI-Bench 的"64@20MHz"证实；学术"52 有效"中的 12 个为填充/无效值，需在解析层处理——top-K/PCA 天然抗噪，管线实测可用 64 全量）；HT40 → len=384 → 192 个复数值 |
| first_word_invalid | 实测恒 0（CH343 板 + 当前链路），解析层仍保留处理逻辑 |
| 实测采样率 | TX 标称 100Hz，RX 实收 ~75-85Hz（seq 差分 loss ~25%，待校准期排查：broadcast 无 ACK/TX 发送背压） |
| CSI 功能总开关 | **`CONFIG_ESP_WIFI_CSI_ENABLED=y`**——不设则 `esp_wifi_set_csi*` 全部裸 ESP_FAIL（本次最大排障成果，原厂例程 defaults 里有、文档无突出说明） |

## 2. 排障战记录（按时间序，全部固化进代码/工具）

1. **sdkconfig.defaults 的 2000000 波特没生效** → `ESP_CONSOLE_UART_BAUDRATE` 仅在 `ESP_CONSOLE_UART_CUSTOM=y` 时可设（DEFAULT 模式强制 115200）；手改 sdkconfig 需 `idf.py reconfigure` 才重生成 sdkconfig.h。
2. **COM13 零输出** → TX 板插的是 S3 原生 USB 口（"USB 串行设备"），控制台在 UART0；固件改 `CONFIG_ESP_CONSOLE_USB_SERIAL_JTAG` + `esp_console_new_repl_usb_serial_jtag()`。
3. **RX 反复重启** → `esp_wifi_set_csi_config` 返回 ESP_FAIL 被 ESP_ERROR_CHECK 打断 → 根因见上表第 4 行（CSI 总开关）。中途为定位做过：全调用插桩（CHK 宏）、对齐 esp-radar 初始化（netif_sta/protocols/set_mac 时序/peer 显式信道）、HT40 试验、烧原厂 csi_send/csi_recv 配对对照（原厂能通 → 锁定工程配置差异 → diff sdkconfig 找到开关）。
4. **CSV 首值 `%h u`** → ROM `ets_printf` 不认 `PRIu16`（%hu），必须 cast 后 `%d`。
5. **串口工具两个自坑** → DTR+RTS 同拉=进下载模式（改仅 RTS 的 esptool 序列）；复位后清缓冲正好洗掉启动日志（先清后复位）。
6. Hyper-V 保留端口段（1883/8123 等）bind 被拒——上轮已知，本轮未再踩。

## 4. 呼吸实验结果（2026-10-05，第三次摆位成功）

| 轮次 | 摆位 | 主峰 | 峰值比 | 结论 |
|------|------|------|--------|------|
| test1（120s） | 人刚就位/在旁 | 19.3bpm 弱峰 | ~3.4 | 几何不对 |
| test2（180s） | 桌面摆位 | 8-10bpm（幅度22） | 中位 2.45 | 位置仍不对（连线过腹部高度） |
| **test3（180s）** | **用户调整摆位后** | **8.8bpm（幅度57）** | **中位 3.87** | **成功** |

**test3 定量结果**（阈值按实测标定 3.5 后）：98/151 窗有效（65%），**呼吸率中位 8.8 bpm，四分位 8.4–9.2**，全程分段中位 9.1→9.1→9.3→9.1→8.2→8.4 稳定，首尾各 20s 窗口未满无效（正常）。FFT/自相关一致率 85%。瀑布图 `output/breath_test3_wf.png`。
**待用户口头确认**：3 分钟计数的呼吸次数（8.8bpm×3min≈26-27 次，若用户数得 25-30 次即完成真值闭环）。

### 本轮算法沉淀（全部过回归：对拍 4/4、M1 12/12）

1. **丢包重采样**（`resample_uniform`）：真实链路随机丢包使时间轴有洞，块平均跨洞混叠波形→FFT 展宽；按时间戳线性插值回 100Hz 均匀网格。合成数据无损包时为恒等变换（对拍契约保持）。
2. **死子载波剔除**：实测 sub0 恒 0（HT20 的 64 值含填充位），按 std==0 剔除。
3. **门控阈值实测标定**：min_peak_ratio 5.0（合成数据设定）→ **3.5**（真人桌面坐姿峰值比中位 3.87/最大 4.91），对应 Vital-Radio 部署期标定原则；Python/C 两侧同步。

## 5. 夜间追加（2026-10-05 晚，侧卧重测引发的连环排障与算法突破）

1. **晚高峰信道拥塞实锤**：19:34 侧卧重测到达率仅 37/s（TX 发包率 100/s 整、RSSI 满格、RX drop=0）→ 63% 丢在空口。扫谱定位：自家路由器（2.4G）在 **信道 8**（11ax，99% 信号，晚 3 终端），板子默认 ch11 正好被其频谱压住。下午同屋仅 6% 丢包——时间对得上。
2. **换信道连环坑**：
   - 运行时 `channel` 命令把 TX 射频切坏（set_channel 返回 OK、send_err=0，但两个信道都听不到它）——**固件 bug，待修**（疑与 ESP-NOW peer 重建时序竞态有关）；规避法：改 sdkconfig 默认信道重刷（TX_DEFAULT_CHANNEL 11→1）。
   - **打开 COM13 会复位 TX**：S3 USB-Serial-JTAG 模拟自动复位电路，pyserial 开口默认拉 DTR/RTS 触发复位（CH343 的 RX 板免疫）→ serial_io 已修（开口前置低两线）。
   - 信道无持久化（NVS）——复位即回默认，列入固件待办。
3. **信道 1 效果**：丢包 63%→1.4%，fs=99.9 整。
4. **侧卧重测（干净信道）**：谱峰干净聚在 8.2–9.4bpm（无干扰杂峰），两法一致窗锁定 9.1bpm——**信号存在且真实**，但逐窗峰值比仅 2.0（弱信号谱底抬高稀释均值分母），且与走动的标量统计（2.15/43%）不可分——放宽阈值必然重蹈特异性破线。
5. **相干轨迹确认（原型验证通过，真值闭环，待正式集成）**：宽进（ratio≥2.0 + FFT/AC 一致 + 功率排除尖峰）→ 90s 邻域中位 ±0.5bpm 轨迹确认。实测：侧卧 0%→**19%**（轨迹 9.37bpm，**真值 29 次=9.67bpm，MAE 0.30**）、仰卧 26%→**70%**（9.26bpm）、走动→**0%**（特异性完美）。**侧卧问题从现象定位到算法正解，一次闭环**；下一步：dsp.py 正式实现 + csi_core.c 镜像 + 对拍回归 + 判据更新。另：下午拥堵信道的 seg2 真值 7.7bpm 与当时的少数子载波信号（7.0–7.3bpm）其实吻合——两轮侧卧的呼吸信号都被看见了，输的从来只是聚合与门控。
