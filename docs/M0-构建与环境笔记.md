### 1.2 踩坑记录（重要，已固化进 idf.bat）

| 坑 | 现象 | 解法 |
|----|------|------|
| Git Bash 不受支持 | `export.sh` 直接报错 "MSys/Mingw is not supported" | 走 `cmd + idf_cmd_init.bat` 路线，DOSKEY 宏在非交互 cmd 无效 → wrapper 直接 `python tools\idf.py` |
| MSYSTEM 泄漏 | cmd 继承 Git Bash 的 `MSYSTEM` 变量，idf.py 报 "no longer supported" | wrapper 里 `set "MSYSTEM="` |
| **ccache 间歇性失败** | 随机子命令挂掉：`ar` 拒绝访问 / `ccache: execute_noreturn of gcc.exe failed`（gcc 本体可独立运行）；两个工程各失败 2 次后换法才过 | **`--no-ccache`**。注意：`-DCCACHE_ENABLE=0` 无效（idf.py 在 tools.py:658 会追加自己的值覆盖用户 -D）；`IDF_CCACHE_ENABLE=0` 环境变量被 click 按标志位误解析反而开启。疑似根因是杀毒软件实时扫描锁新建的 .o/.a——**建议后续把 `E:\ESP32Project`、`E:\Espressif\tools` 加入 Defender 排除列表**（需管理员权限，暂未做） |

## 3. 源码研究结论

### 3.1 收发关键默认参数（`csi_send`/`csi_recv` 的 `app_main.c`，ESP32-S3 分支）

| 参数 | 上游默认值 | 对本项目的含义 |
|------|-----------|----------------|
| 信道 | **11**（`CONFIG_LESS_INTERFERENCE_CHANNEL`） | TX/RX/路由器三者必须一致；部署时按扫描结果改 |
| 带宽 | **HT40 + `SECOND_CHAN_BELOW`**（2025/2026 新版默认！） | 方案定的是 **HT20 为默认**——M1 自研固件时改回 `WIFI_BW_HT20` + `WIFI_SECOND_CHAN_NONE`；或先按 HT40 实测对比 |
| ESP-NOW | `WIFI_PHY_MODE_HT40` + `MCS0_LGI`，广播 `ff:ff:ff:ff:ff:ff`，payload=4 字节计数 | RX 从 payload 取发包序号（丢包率统计可直接用） |
| 发包率 | **100 Hz**（`CONFIG_SEND_FREQUENCY`） | 与论文配置一致 |
| 省电 | `esp_wifi_set_ps(WIFI_PS_NONE)` 已内置 | 评审 P2-8 项上游已处理 |
| TX MAC | `1a:00:00:00:00:00`（RX 按此过滤 CSI 来源） | 自研固件沿用此过滤模式 |

### 3.2 CSI 配置结构（ESP32-S3 用 `wifi_csi_config_t`，方案 §5 M0-3 要求的定稿基础）

```c
// csi_recv 默认（S3 分支）：
.lltf_en = true, .htltf_en = true, .stbc_htltf2_en = true,
.ltf_merge_en = true, .channel_filter_en = true,
.manu_scale = false, .shift = false,
```

- 输出 CSV 含 **`first_word_invalid`** 字段——官方确认 CSI 缓冲首字可能无效（对应 esp-csi issue #45/#137），解析时须处理。
- data 为 **int8 I/Q 交错原始字节**（`info->buf[i]` 直接按有符号打印）。
- **子载波数待实测定稿**（HT40 预期 len=128；切 HT20 预期 52）——这是 M0 验收项，实测后写入 M1 固件常量。

### 3.3 增益补偿机制（`esp_csi_gain_ctrl`，S3/C3/C5/C6 专属）

- 问题：AGC 增益跳变会污染 CSI 幅度（呼吸信号的量级！）。
- 机制：前 100 包记录 `agc_gain`/`fft_gain` 基线 → 之后按 `compensate_gain` 系数逐子载波乘回幅度。
- **结论：本项目以幅度为主，此机制必须保留**；`CONFIG_FORCE_GAIN` 可选强制锁定增益（部署后实验对比）。

### 3.4 console_test 上位机工作流（README）

1. PC 运行 `console_test/tools/esp_csi_tool.py -p <UART口>`（**必须用 UART 口，不能用 USB Serial/JTAG 口**；先 `pip install -r requirements.txt`，与 idf.py monitor 互斥）。
2. 功能：CSI 子载波波形（可开滤波）、RSSI 波形、雷达模型（**有人/无人 + 运动/静止**）、路由器连接配置（RX 可作 STA 连家里路由——与方案架构一致）、**动作标注采集**（CSI 存文件供后续 ML 训练——M1 标注工具的现成起点）。

1. TX 烧 `csi_send`、RX 烧 `console_test`（`idf.bat -p COMx flash monitor`，波特率 921600）。

3. **实测记录**：实际 `len`（子载波数）与 `first_word_invalid` 行为（HT40 与 HT20 各测一次）→ 定稿 M1 固件的带宽选择与解析规则。

5. 人在 LOS 上走动/静止，肉眼确认 CSI 幅度可见变化。
